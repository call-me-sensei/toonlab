# ToonLab Agent Resources

These are downloadable AI coding agent resources for developers using ToonLab
runtime features in their own apps. They are not maintenance instructions for
this repository.

The recommended agent workflow starts from an existing scene: apply focused
shaders/vegetation/water/post, find assets through Gallery or MCP, and author
bounded portable outputs. `outdoor-world`, `karst-cliff-construction`, and
current Sky/Cloud guidance are experimental research/qualification resources,
not a promise of reliable one-shot scene construction.

Layout:

- `codex/AGENTS.md` — shared Codex-style runtime usage guide.
- `claude/CLAUDE.md` — Claude Code wrapper for the shared guide.
- `cursor/toonlab.mdc` — Cursor rule file; copy it to `.cursor/rules/` in a
  project if desired.
- `skills/codex/` — Codex-oriented feature skills.
- `skills/claude/` — Claude-oriented feature skills.
- `references/` — public anime art direction, style routing, MCP discovery,
  runtime-boundary, sourcing-policy, and custom-gap contracts used by every
  agent integration.

Recommended feature skills (start with `game-dev` for existing-scene
integration and `asset-sourcing` for Gallery/MCP work):

These text-only resources ship with the npm package beside the runtime source.
The package does not include ToonLab lab applications, examples, review
fixtures, models, textures, or other redistributed visual/media assets.
First-party grass geometry and materials are generated by runtime code; the
optional CC0 mannequin resolves from immutable public R2 rather than npm.

All integrations share one non-optional authored-asset rule: every renderable
root needs a stable target ID/domain, and every material slot needs a stable
material ID plus semantic role in the versioned ToonLab material contract.
Root-only labels do not make multi-material assets bundle-ready. Strict mode
blocks incomplete assets; advisory mode must report them as incomplete.
