# ToonLab 0.4.10 release-candidate notes

0.4.10 is a remediation and agent-guidance release. It packages the corrected
cross-agent outdoor-world guidance that missed 0.4.8, and it closes additional
runtime defects found while re-auditing the full 0.4.7 quality register.

This document records code and contract verification. It is not visual
approval. Publication still requires a clean-tarball P18 capture covering the
grass silhouette and LODs, rock/ground palette, tree shadows and fog, shoreline,
underwater composition, clouds, and the required camera views.

`AGENTS.md`, the Cursor rule, the Claude/Codex skill trees, and the shared
runtime/geology references route other coding agents to the same contracts.
The three new skills provide:

- geology-aware modular cliff construction, including overlap, burial,
  rotation, scaling, shared face planes, asset-size checks, and explicit
  handling of placement ceilings;
- explicit Call Me Sensei style-preset selection and resolved-preset checks;
- readiness, multi-view capture, console, LOD, and independent-review gates.

The skill text does not claim an automatic cliff builder, terrain burial
solver, or stable full-world coordinator. Those remain host-owned or future
systems.

## Runtime corrections

### Grass and vegetation

- First-party Call Me Sensei grass remains generated from ToonLab-owned code;
  the npm tarball contains no grass media or retained third-party clump.
- `bladeBudget()` reports authored and drawn blades per LOD.
- LOD0/1/2 retain coverage rather than changing the apparent ground color.
- The Call Me Sensei bend exponent is explicitly `1.3`.
- Hex, number, and `THREE.Color` inputs now follow the documented sRGB
  convention without double decoding.
- The signature meadow adopts the sampled terrain with an exact neutral
  `[1, 1, 1]` multiplier, preventing pale ground from bleaching its roots;
  its default hue-shift/desaturation remain zero.
- `BranchTree` now carries a portable lit/shadow/crown palette and independent
  `coverageScale`; trunk `bend`, `twist`, and `radiusTop` change the generated
  geometry.
- The tree settings validator accepts its own `limbs` and `cloud-cards`
  defaults, and the public description distinguishes lateral children from
  the continuing leader.
- Node-backend trunks honor `trunkReceiveShadow`; tree foliage exposes
  `setSceneFog()` and the public `syncFoliageFog` helper.

### Water

- `WaterScenePasses` invokes optional
  `object.userData.onWaterPass(camera, passKind)` hooks for grab and reflected
  cameras and restores object state even when rendering throws.
- Pass statistics expose the configured maximum, actual scene renders, pass
  names, and render-target sizes.

### Post-processing

- The default vignette radius lies inside the image frame.
- `setSize()` resizes owned render targets without silently resizing the host
  renderer. A host may opt into the former behavior with `ownsRenderer: true`.
- The pipeline exposes `compositeCamera` for integration and diagnostics.

### Ambient FX and texture guidance

- Public effect overrides use the unambiguous `densityScale` name; `density`
  remains a compatibility alias.
- `emitNow(camera)` makes construction-time stats and first captures explicit
  rather than pretending an un-updated effect has emitted particles.
- Texture-generation guidance now warns when display-space ramps clip HDR
  tint and erase cel bands or vertex shading.

## Documentation and package boundary

- Runtime-boundary text, repository-only warnings, examples, settings
  reference, main/alias versions, and paired skills target 0.4.10.
- README documentation links use durable GitHub URLs because repository docs
  are deliberately excluded from the npm tarball.
- The package still contains no third-party media packs, mannequin binary,
  private-CDN URL, repository lab, example, or audit artifact.
- OSS and Pro asset instructions remain capability-detected: OSS uses the
  local/public CC0 tools when available; Pro uses public gallery retrieval.
  Official URLs must resolve under immutable `assets.toonlab.io/official/`.

## Remediation accounting

The generated [0.4.10 disposition](0.4.10-remediation-disposition.md) classifies
all 267 historical findings: 67 were already resolved in 0.4.8, 27 are
resolved in 0.4.10, one host-side misuse is resolved through distributable
guidance, 26 require new systems, 126 remain explicit non-blocking follow-up,
and 20 are superseded or not package defects. All 46 historical blockers have
an explicit disposition; none is left unclassified.

Not claimed in 0.4.10:

- automatic cliff construction, burial, or terrain-formation solvers;
- waterfall/cascade and volumetric whitewater-mass systems;
- arbitrary-axis water;
- a full packaged Lighting System;
- catalog-wide new large-cliff donor content;
- fully asynchronous post rendering;
- source-bound AmbientFx waterfall spray or mist-coverage estimation.

## Verification-tool note

`npm run verify:skills` validates frontmatter, all 17 Claude/Codex pairs,
local references, routing, and the new semantic contracts. The generic
skill-creator Python `quick_validate.py` was not runnable in this workspace
because its Python environment lacks PyYAML. This is documented as a tooling
dependency limitation, not treated as evidence that the package validator ran.
